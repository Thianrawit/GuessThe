1. สรุปภาพรวมสถาปัตยกรรมเครื่องเล่นสื่อ (Dual-Player Architecture):
   - พัฒนาระบบเครื่องเล่นคู่สลับฟันปลา (A/B Ping-Pong Buffering) ผ่าน `DualYouTubePlayerManager` เพื่อขจัดปัญหาโฆษณา YouTube แทรกระหว่างเล่นเกม 100%
   - เครื่องเล่นคู่ถูกสร้างเป็น Persistent Stage ใน DOM ซึ่งไม่ถูกทำลายหรือ Reload ซ้ำเมื่อมีการสลับหน้าจอ (No IFrame Reload / No White Flash)
   - มีระบบ Autoplay Warm-up (`warmUp()`) ปลดล็อก Autoplay Policy ของเบราว์เซอร์ล่วงหน้าทันทีที่ผู้ใช้กด "สร้างห้อง", "เข้าห้อง", หรือ "เล่นคนเดียว"
   - จัดสรรเวลาให้ Background Player เผาโฆษณาล่วงหน้านานกว่า 22 วินาที (ช่วง Snippet 3s + Answering 10s + Reveal 5s + Leaderboard 4.5s) ทำให้วิดีโอข้อถัดไปพร้อมเล่นทันที 100%

1. แก้ไขปัญหาจำนวนข้อไม่ตรงตามที่ตั้ง (Question Count Mismatch):
   - สาเหตุ: ใน `lobby-screen.ts` มีการเรียก `ensureQuestionsPrepared()` ไว้ล่วงหน้าตั้งแต่ตอนเข้า Lobby ขณะที่ค่าคอนฟิกยังเป็นค่าเริ่มต้น (`'all'`) ทำให้ชุดคำถามมีขนาดตามเพลงทั้งหมดในคลัง เมื่อผู้ใช้ปรับ dropdown จำนวนข้อ (เช่น 5 หรือ 10) ใน `game-controller.ts:startGame()` มีเงื่อนไข `if (this._questions.length === 0)` ซึ่งไม่ทำงานเพราะมีคำถามเดิมอยู่แล้ว
   - การแก้ไข:
     * `src/game/game-controller.ts`: ปรับปรุง `setConfig()` และ `startGame()` ให้ตรวจสอบจำนวนข้อที่แท้จริง (`targetCount`) หากจำนวนข้อใน `this._questions` ไม่ตรงกับที่ตั้ง ให้ตัดทอน (`slice`) หรือสร้างใหม่ (`generateQuestions`) ให้ตรงเป๊ะ 100% (โดยเก็บข้อที่ 0 ที่พรีโหลดไว้เดิมได้)
     * `src/screens/lobby-screen.ts`: เพิ่ม `change` event listener ให้ `#select-question-count` อัปเดต `gameController.setConfig` ทันทีที่ผู้ใช้เปลี่ยนตัวเลือก

2. แก้ไขปัญหาปกคลิปขึ้นมาทับตัวเลขนับถอยหลัง (Countdown Overlay Covered by Video):
   - สาเหตุ: `#dual-player-stage` อยู่ใน `document.body` ด้วย `position: fixed; z-index: 15;` ขณะที่ `#countdown-overlay` อยู่ใน `#media-viewport` ภายใน `#app` (ซึ่งไม่มี z-index) ทำให้ stage ของวิดีโอลอยทับ `#countdown-overlay` และตอน mount มีการเซ็ต `opacity: 1` ทันที
   - การแก้ไข:
     * `src/engine/youtube-player.ts`: เพิ่มเมธอด `setStageVisible(visible: boolean)` ให้สามารถซ่อน stage แบบเด็ดขาด (`opacity: 0; visibility: hidden; pointer-events: none;`)
     * `src/screens/game-screen.ts`: ในช่วง Initial Buffering และ Countdown (3..2..1) จะสั่ง `dualPlayerManager.setStageVisible(false)` อย่างเข้มงวด ทำให้ตัวเลขนับถอยหลัง 3..2..1 บนจอดำใน `#media-viewport` เด่นชัด 100% ไม่ถูกปกคลิปหรือ iframe บดบัง

3. ปิดชื่อคลิปเพื่อป้องกันสปอยล์ 100% (Anti-Spoiler Title Masking):
   - สาเหตุ: แถบ anti-spoiler เดิมอยู่ใน `#app` จึงถูก `#dual-player-stage` ทับ
   - การแก้ไข:
     * `src/engine/youtube-player.ts`: สร้างแถบ `#dual-anti-spoiler-bar` ปักหมุดไว้ที่ส่วนบนสุดของ `#dual-player-stage` โดยตรง (สูง 72px, `z-index: 30`, พื้นหลังสีทึบ `#0a0a14` พร้อมโลโก้ GuessThe? และ badge) บังทับส่วน Title, Share Button และ Channel Avatar ของ YouTube Embed มิดชิด 100%
     * มีเมธอด `updateAntiSpoiler(mode, showTitleMask)` เพื่อควบคุมการแสดงแถบปิดชื่อช่วงทาย และจะเฟดออกเฉพาะช่วงเฉลย (Reveal)

4. แก้ไขปัญหาสล็อตคลิปสับสน เอาคลิปถัดไปหรือคลิปที่ทายแล้วมาขึ้นก่อน (Deterministic Slot Synchronization):
   - สาเหตุ:
     * มี ID ซ้ำซ้อน (`#yt-player-a` และ `#yt-player-b`) ทั้งใน `#dual-player-stage` และใน template ของ `game-screen.ts` ทำให้ `document.getElementById` ไปดึง element เปล่าใน `#app` มาจัดการสไตล์ผิดตัว
     * ระบบเดิมสลับสล็อตด้วยการ toggle สลับไปมาตาม timeout (`switchActivePlayer`) ซึ่งหากหลุดจังหวะหรือใน multiplayer ฝั่ง client จะทำให้สล็อตไม่ตรงกับข้อที่กำลังเล่น
   - การแก้ไข:
     * `src/screens/game-screen.ts`: ลบ container ซ้ำซ้อนใน template ออก เปลี่ยนเป็น `#dual-player-anchor` สำหรับระบุพิกัดเท่านั้น
     * `src/engine/youtube-player.ts`: จัดการ DOM wrappers (`#dual-slot-wrapper-a` และ `#dual-slot-wrapper-b`) โดยตรงผ่าน object reference
     * พัฒนาระบบ Deterministic Slot Sync: `syncActiveSlot(questionIndex)` กำหนดสล็อตอย่างแม่นยำตามสูตรคณิตศาสตร์:
       - ข้อคู่ (0, 2, 4, ...): สล็อต A เป็น Active Slot เสมอ
       - ข้อคี่ (1, 3, 5, ...): สล็อต B เป็น Active Slot เสมอ
     * Background Slot จะถูกตั้งค่าเป็น `opacity: 0; visibility: hidden; pointer-events: none; z-index: 1;` ตลอดเวลาการเผาโฆษณาและพรีโหลดเบื้องหลัง จึงไม่มีภาพคลิปถัดไปหรือคลิปเก่าหลุดออกมาให้เห็นแน่นอน 100%
