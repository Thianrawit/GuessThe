================================================================
Review IDE — การแก้ปัญหา StreamResolver & Invidious Fallback (Zero-Hang & Resilient Media)
================================================================

1. ปัญหาเดิมที่พบ (Root Cause Analysis):
----------------------------------------
- StreamResolver รันลูป Invidious instances แบบ Sequential (เรียงตัวทีละอัน) โดยมี timeout 3.5 วินาทีต่อ instance ทำให้เมื่อ Invidious public instances ส่วนใหญ่ติด CORS หรือถูกบล็อก ตัว resolver ต้องใช้เวลารอรวมถึง 10-14 วินาทีก่อนจะ error
- อาการที่เกิดคือหน้า Loading (Initial Buffering) ค้างเกิน 10 วินาทีจน trigger hard timeout แล้วยังไม่พร้อม
- เมื่อ Invidious ไม่สามารถดึง direct stream ได้ ตัว <video id="game-media"> ไม่มี src ทำให้เกิดข้อผิดพลาดในการเล่นสื่อ และไม่มีเสียง/วิดีโอขึ้นมาในเกม
- ข้อผิดพลาด `TypeError: Cannot read properties of undefined (reading 'startTime')` เกิดจาก external script/extension (Performance Observer/Web Vitals) ที่พยายามอ่าน PerformanceEntry ใน browser
- `Failed to execute 'postMessage' on 'DOMWindow'`: เกิดจาก YouTube IFrame API ในโหมด localhost ที่ไม่มีการระบุ `host: 'https://www.youtube.com'` และ `enablejsapi: 1` ทำให้ widget API สับสนเรื่อง origin
- อาการ "เพลงไม่ขึ้น":
  1) คอนเทนเนอร์ `#game-yt-player-wrap` ถูกเซ็ตสไตล์ `hidden` (`display: none`) ใน HTML และโค้ดเดิมไม่ได้ปลดคลาสออกเมื่อเป็นเพลงประเภท audio ส่งผลให้ Chromium หยุดการทำงานของ IFrame (IFrame execution & audio playback suspended)
  2) ฟังก์ชัน `startQuestionFlow` ทำการทำลายและสร้าง IFrame ใหม่โดยไม่ได้ await ส่งผลให้ตอนที่ `playSegment` สั่งเล่น ตัวเล่นยังไม่พร้อม หรือถูกทำลายทิ้งไปก่อน
  3) ใน `createYouTubePlayer` ไม่ได้ส่ง `start` เข้าไปใน `playerVars` ทำให้คลิปพยายามเริ่มเล่นที่ 0 วินาที ซึ่งมักจะติดโฆษณา Pre-roll Ad ของ YouTube

2. สิ่งที่ดำเนินการแก้ไข (Implemented Solutions):
-----------------------------------------------
- ปรับปรุง `src/engine/stream-resolver.ts`:
  * เปลี่ยนจากการ fetch แบบ sequential เป็น Concurrent Racing ด้วย `Promise.any` คิวรีทุก instance พร้อมกันแบบคู่ขนาน
  * ลด timeout เหลือ 2000ms โดยหากไม่มี instance ใดตอบกลับ จะ reject ทันทีภายใน 2 วินาที ไม่มีการค้าง 14 วินาทีอีกต่อไป
  * เพิ่มตัวแปร `instancesCORSBlocked` จดจำสถานะใน session ทันทีที่ public instances ติด CORS ครั้งแรก ข้อถัดๆ ไปจะไม่ส่ง network request ไปให้ console ขึ้นสีแดงซ้ำซาก และสลับไป YouTube fallback ได้ทันทีใน 0ms
- ปรับปรุง `src/engine/youtube-player.ts`:
  * เพิ่ม `host: 'https://www.youtube.com'`, `enablejsapi: 1`, `start: startTime`, และ `widget_referrer: window.location.href` ใน `createYouTubePlayer` และ `createPreviewPlayer`
  * ปรับให้ `createYouTubePlayer` รองรับการนำ IFrame เดิมกลับมาใช้ซ้ำ (Player Reuse) ผ่านคำสั่ง `loadVideoById` โดยไม่ต้องทำลายและสร้าง IFrame ใหม่ทุกข้อ
  * ปรับปรุง `prebufferAt` ให้ `unMute()` และตั้งระดับเสียง 100% หลังพรีบัฟเฟอร์เสร็จ เพื่อให้พร้อมเล่นทันทีเมื่อเข้าสู่ Snippet Phase
  * ปรับปรุง `playSegment` และ `playReveal` ให้ `unMute()`, `setVolume(100)`, และ `seekTo(startTime)` อย่างแม่นยำ
- ปรับปรุง `src/screens/game-screen.ts`:
  * เปลี่ยนคอนเทนเนอร์ `#game-yt-player-wrap` จากการใช้ `hidden` (`display: none`) มาใช้ `opacity-0` / `opacity-100` แทน เพื่อให้ IFrame มีขนาดและทำงานใน DOM ตลอดเวลา ไม่ถูก Browser Freeze เสียง
  * โหมดทายเพลง (Audio): ใช้ `media-curtain` (`z-20 bg-[#0a0a14]`) ปิดทับภาพวิดีโอไว้ แสดง Audio Visualizer ขณะที่เสียงเพลงเล่นผ่าน YouTube Player เต็ม 100%
  * โหมดทาย MV (Video): ซ่อน `media-curtain` เพื่อเปิดให้เห็นคลิปภาพวิดีโอ
  * แก้ไข `startQuestionFlow` ให้ตรวจสอบ `currentLoadedVideoId` ก่อน หากเป็นคลิปเดียวกับที่พรีบัฟเฟอร์ไว้ในขั้นตอน Initial Buffering จะไม่สั่งโหลดซ้ำ ทำให้เพลงเริ่มเล่นได้ทันทีเมื่อนับถอยหลังจบ
  * เพิ่ม Background Prebuffering ของข้อถัดไปในหน้า Intermediate Leaderboard แบบไร้รอยต่อ
