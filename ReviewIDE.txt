## Requirements Addressed
1. **Two-Stage Question Flow (Snippet Playing -> Answering Countdown)**:
   - Separated snippet duration (`snippetDuration`) from answer timer (`guessDuration`).
   - During snippet playback (Stage 1), choice buttons are strictly **DISABLED** (`opacity-60`, `cursor-not-allowed`) and cannot be clicked. Status indicator informs players to wait for snippet completion.
   - Once snippet completes (Stage 2), choice buttons become **ENABLED**, and the Answer Timer Bar starts counting down from 100% to 0%.
   - When <= 3s remains in the answer timer, Urgency Effects activate (flashing neon red-orange bar, heartbeat scale pulse, 🚨 icon, red timer text).
2. **Speed-Based Scoring System**:
   - For correct answers: Points = Base Points - Time Deduction.
   - Deduction rule: For every 500ms (0.5s) elapsed, deduct 0.5 points (`Math.floor(timeUsedMs / 500) * 0.5`).
   - Minimum score for correct answers is clamped at 0.5pt.
   - Incorrect answers or timeouts (0s) yield 0 points.
   - Formatted scores display integers cleanly (e.g., 10) or with one decimal place (e.g., 9.5).
3. **Multiplayer Leaderboard Crowns vs Solo Mode**:
   - Ranked from highest score to lowest score.
   - Multiplayer mode:
     - Rank 1: Gold Crown (`👑` with amber glow & bounce).
     - Rank 2: Silver Crown (`👑` with silver monochrome styling).
     - Rank 3: Bronze Crown (`👑` with sepia/bronze styling).
     - Rank 4+: Rank index (`#4`, `#5`, etc.).
   - Solo mode: Crowns are completely hidden in front of the player name.
4. **Zero Thumbnail Bleed in Audio Mode**:
   - Ensured `#yt-player-container` has `opacity-0` during audio guessing.
   - Made `#media-curtain` 100% pitch solid black (`bg-[#0a0a14] z-20`) without any transparency or backdrop blur leak.
   - Unveils video smoothly at full opacity during the reveal phase.

- **Problem Solved**: Eliminated annoying YouTube pre-roll ads during real gameplay while keeping YouTube URL compatibility.

  1. `src/screens/track-editor-screen.ts`: Kept YouTube IFrame API & oEmbed for easy title fetching and visual timeline timeline scrubbing.

- **New Module `src/engine/stream-resolver.ts`**:

- **New Module `src/engine/media-engine.ts`**:
  - `initAndPrebuffer`: Fetches direct stream and prebuffers at `startTime` during 3-2-1 countdown.
  - `playSnippet`: Unmutes, plays for `snippetDuration`, and auto-pauses/mutes.
  - `playReveal`: Seeks to `revealStartTime`, unhides video, and plays for `revealDuration`.
  - `stop` & `destroy`: Safely stops and cleans up DOM media elements.
## Issue Analysis: Invidious API CORS Failure on GitHub Pages
- **Root Cause**:
  1. GitHub Pages runs under `https://thianrawit.github.io`. Direct client-side `fetch` calls to third-party Invidious instances are blocked by browser Same-Origin Policy (CORS) because the public Invidious instances do not return `Access-Control-Allow-Origin: *`.
  2. Public Invidious instances have disabled API endpoints or are blocked/throttled by YouTube.
  3. Consequently, all 7 Invidious instances failed sequentially until the 6-second timeout occurred, causing questions to be skipped without audio.
- **Resilient Solution Implemented**:
  1. `stream-resolver.ts`: Optimized to fail fast (~1.2s) when browser CORS rejection is detected instead of stalling gameplay.
  2. `media-engine.ts` (Dual Engine):
     - **Primary**: Direct stream HTML5 (`<video>` / `<audio>`) for direct media links (.mp3/.mp4) or when Invidious proxy succeeds.
     - **Fallback**: Seamlessly falls back to optimized YouTube Privacy-Enhanced Player (`https://www.youtube-nocookie.com`).
     - **Anti-Ad Optimization**: Directly sets `start: Math.floor(startTime)` in `playerVars` to bypass the 0-second pre-roll ad slot.
     - Music and video now play consistently without being skipped.
  3. `src/vite-env.d.ts`:
     - Added `host?: string` to `YT.Player` options interface to support `https://www.youtube-nocookie.com`.
     - Production build verified: `npm run build` (Exit code: 0).

## Page Reload Handling & Session Persistence
- **Problem**: When user reloads the browser at `#/game`, the in-memory state is wiped, getting stuck at `#/game` with "ไม่พบคำถาม".
- **Solution**:
  1. `src/game/game-controller.ts`:
     - Added `SavedSession` persistence to `sessionStorage`.
     - `saveSession()`: Persists active questions, current index, config, and player scores whenever game starts or updates.
     - `restoreSession()`: If refreshed while game is in progress (`currentIndex < totalQuestions`), automatically restores the solo session so player stays in the game.
     - `clearSession()`: Automatically clears session on `gameOver()`, `resetToLobby()`, or `destroy()`.
  2. `src/main.ts` & `src/screens/game-screen.ts`:
     - Route `/game` checks if an active question exists or if a session can be restored.
     - If game has ended or cannot be restored, automatically redirects immediately to `#/` (home) instead of getting stuck on `#/game`.
- Verified with `npm.cmd run build` (Exit code: 0).
